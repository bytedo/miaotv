# TVBox 访问控制

TVBox 配置接口可以按 Token、IP 和请求频率限制访问。这些开关默认关闭；关闭 Token 验证时，知道配置地址的人就可以读取配置。

管理员在后台的“TVBox 安全”中保存这些设置。普通使用者只需取得可用的配置链接，导入方法见 [TVBox 接入](./TVBOX.md)。

## Token

### 全局 Token

启用“Token 验证”，生成或填写 Token 后保存，再把完整链接填入 TVBox：

```text
https://tv.example.com/api/tvbox?token=YOUR_TOKEN
```

全局 Token 没有绑定某个用户，也不会继承某个用户专属 Token 的源限制。它仍受源启用状态、内容显示设置、IP 白名单和限流等规则影响。

### 用户 Token

在后台“用户管理”中，为用户生成 TVBox Token，并选择可访问的视频源。没有选择源时，表示不额外限制来源范围。

请求带用户 Token 时，服务端先查找对应账号，再检查账号是否仍有效。源权限来自该用户的 TVBox 设置。重新生成 Token 后，旧链接需要更新。

验证顺序是用户 Token、全局 Token；关闭 Token 验证时允许没有匹配 Token 的请求。即使已经为用户配置了专属 Token，全局 Token 仍然是另一条可用入口，因此不要把全局 Token 发给需要限制源范围的用户。

Token 是持有者凭据。带 Token 的链接、二维码、浏览器历史和访问日志都可能包含它，分享截图和日志前应删去该参数。Base64 格式不会加密 Token。

## IP 白名单

启用 IP 白名单后添加允许访问的地址或网段。支持单个 IPv4、IPv6 地址、CIDR 和 `*`；`*` 表示允许任意地址。当前实现对白名单为空的情况不执行限制。

示例格式如下，需换成部署时实际使用的地址：

```text
192.168.1.0/24
2001:db8::/32
```

服务端优先使用连接地址；只有配置了 `TRUST_PROXY_HEADERS=true`，才会读取 `X-Forwarded-For`、`X-Real-IP` 等转发头。设置前应确认入口代理会覆盖客户端传入的这些头，部署方式见[可信网络说明](../authentication/TRUSTED_NETWORK.md)。

无法取得可信客户端 IP 时，非通配符白名单会拒绝请求。家庭宽带和移动网络的公网地址可能变化，配置后需要从 TVBox 所在网络验证。

## 请求频率

限流默认值为每分钟 60 次，开启后按客户端地址和分钟窗口计数。取不到地址时，请求会共用 `unknown` 计数桶；通过同一出口访问的设备也可能共用额度。

当前限流依赖缓存读写。缓存不可用时会放行，而且计数更新不是原子操作，因此它适合减少重复刷新，不能代替入口代理的严格限流。

## 成人源筛选的边界

`/api/tvbox` 会检查视频源的 `is_adult` 标记。未传 `filter=off` 时，显示设置来自用户、用户组和站点配置；用户设置优先，多个用户组中有允许项时按允许处理。

当前代码只在“没有传 `filter=off`，且显示设置不允许”时移除成人源。持有有效配置链接的使用者可以添加 `filter=off` 跳过这一步，它没有额外的管理员验证。因此这项功能只是内容显示筛选，不能用来保证账号没有访问权限。

需要限制可获取的源时，应配置用户 Token 的允许源列表，同时控制全局 Token 的分发。TVBox 得到的是源配置，已经导出的上游地址也不会因本站之后的设置变更而自动撤回。

## CMS 代理与 TVBox 的区别

`/api/proxy/cms?url=...` 使用本站的账号和来源授权规则。单独携带 TVBox Token 不会取得这个代理的访问权限。

目标必须同时通过：

- 有效账号或已经配置的可信网络入口检查。
- 当前用户可用 CMS 源的 origin、API 路径和已配置的嵌套 `url` 参数检查。
- HTTP/HTTPS、IP 类型、DNS 和重定向目标检查。
- 接口路径模式检查，例如 `/api.php`、`/provide/vod` 或允许的 CMS 操作。

通过授权后，代理仍会按 `is_adult` 源的 origin 过滤请求，除非带有 `filter=off`。这个参数只影响内容筛选，不会绕过来源或网络目标检查。

完整规则和私网来源限制见[代理与来源授权](../advanced/PROXY_CONFIG.md)。旧文档中“只要 URL 带 `ac=list` 就能代理任意目标”的理解不适用于当前实现。

## 错误与定位

| 响应                             | 常见原因                             |
| -------------------------------- | ------------------------------------ |
| 401 `Invalid token...`           | 启用了验证，但 Token 缺失或不匹配    |
| 403 `Account access denied`      | 用户 Token 对应的账号已失效或被限制  |
| 403 `IP access denied`           | 无法识别客户端地址，或地址不在白名单 |
| 429 `Rate limit exceeded`        | 当前地址在这一分钟内请求过多         |
| CMS 403 `Invalid or blocked URL` | 账号、源授权或网络目标检查未通过     |
| CMS 403 `URL not in whitelist`   | 目标不符合支持的 CMS 接口模式        |

配置接口和搜索接口的共享验证实现在 [proxy-tvbox.ts](../../src/lib/proxy-tvbox.ts)。CMS 代理见[路由实现](../../src/app/api/proxy/cms/route.ts)，相关方案参考了 [DecoTV](https://github.com/Decohererk/DecoTV)。
