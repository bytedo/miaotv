# 信任网络

信任网络允许指定 IP 的匿名设备访问部分只读页面和接口，适合家里的电视或其他不便输入密码的设备。它不会创建账号、签发站长 Cookie 或授予管理权限。

当前放行范围限于非敏感路径的 `GET`、`HEAD`、`OPTIONS` 请求。`/admin`、`/api/admin`、用户设置和修改密码仍需账号认证，接口自己的权限检查也会继续执行。匿名的信任网络身份不能访问需要账号授权的私有媒体源。

## 设置地址范围

有两种方式：

- 在管理后台的“信任网络配置”中启用功能，添加 IP 或 CIDR。这个面板只允许站长修改，需要服务端存储。
- 设置环境变量 `TRUSTED_NETWORK_IPS`，多个地址用逗号分隔，然后重启服务。

例如，只放行两台固定地址的设备：

```dotenv
TRUSTED_NETWORK_IPS=192.168.1.20,192.168.1.30
```

非空的 `TRUSTED_NETWORK_IPS` 会启用信任网络，并覆盖后台保存的开关和列表。要恢复使用后台配置，删除该环境变量或把它清空，再重新创建容器或重启进程。

| 格式           | 示例                  |
| -------------- | --------------------- |
| 单个 IPv4 地址 | `192.168.1.20`        |
| IPv4 网段      | `192.168.1.0/24`      |
| 单个 IPv6 地址 | `fd12:3456:789a::20`  |
| IPv6 网段      | `fd12:3456:789a::/64` |

示例地址要换成自己的网络地址。优先填写设备 IP 或实际使用的子网；私网地址不代表设备可信，访客 Wi-Fi、共享办公网和 Docker 网桥都可能包含其他使用者。

解析器也接受 `*`，它会匹配所有能识别到的客户端 IP。不要在公网实例中用它代替设备列表。

## 反向代理后的 IP

程序先使用运行环境提供的 `request.ip`。Next.js 的 Web Request 通常没有这个字段；这种情况下，默认不会从请求头猜测客户端地址，也就不会触发信任网络。

只有设置 `TRUST_PROXY_HEADERS=true` 后，程序才依次读取：

1. `x-forwarded-for` 中的第一个 IP。
2. `x-real-ip`。
3. `cf-connecting-ip`。

启用前，应保证所有请求都经过受控入口，入口会清除客户端传入的这些头，再写入真实地址，而且用户不能绕过入口直连应用端口。否则客户端可以自行填写一个受信任的 IP。

Docker 中看到的网桥或代理容器地址可能代表所有外部访问者。直接把这类地址加入列表，可能让公网请求也获得免登录读取权限。Cloudflare 或其他 CDN 部署同样需要核对完整的代理链，不能仅凭请求头名称判断它可信。

## 验证与排查

配置后，用新的浏览器会话或无痕窗口分别从受信任和不受信任的设备访问。受信任设备可以读取允许的页面，但访问管理后台仍应要求登录；不受信任设备仍走正常登录流程。

若没有生效，先检查环境变量是否覆盖了后台配置，再检查应用实际收到的客户端地址。没有可验证的 IP 时，程序会保留登录要求。不要通过添加 `*` 排查地址识别问题。

旧配置中的 `blockAdminAccess` 字段仍可能显示在后台，但当前服务端始终要求管理路径使用有效的管理员账号，不会因为这个字段关闭而给匿名设备授予管理员权限。
